01 / The contextThree related terms

Where does PyTorch fit?

Artificial intelligence

The broad field of building systems that perform tasks such as perception, reasoning and decision-making.

Some AI systems use written rules.

Machine learning

A part of AI where models learn patterns from data rather than receiving every decision rule explicitly.

Example: estimate energy use from past measurements.

Deep learning

A part of machine learning that uses neural networks with multiple processing layers.

Example: learn visual patterns in inspection images.

Deep learning is within machine learning; machine learning is within AI.

PyTorch is a tool used to build and train models, especially in deep learning.
Do not equate all AI with neural networks. A neural network is a mathematical model made of connected processing layers, not a literal human brain. PyTorch also handles ordinary numerical calculations; its usefulness is not limited to deep learning.
01 / DefinitionThe tool itself

PyTorch is an open-source framework
for numerical computing and machine learning.

It gives us reusable software for storing numbers, calculating with them, building models and supporting their training.

Python-friendly

We usually write our instructions in Python and call PyTorch's functions.

A framework

A connected collection of tools. We do not have to implement every calculation and training component ourselves.

Open source

Its source code is publicly available to inspect, use and contribute to under its licence.

Python is the language. PyTorch is a framework we use through it.
Read the definition slowly, then unpack each term. A framework supplies building blocks, not a finished solution to every task. PyTorch has C++ interfaces too; Python is our classroom entry point. Open source does not mean the hardware or cloud computation is free.
01 / PurposeAcross engineering disciplines

Different problems. The same need to learn patterns.

Predict a number

Use weather and building measurements to estimate electricity demand.

Input: measurements
Output: estimated energy use

Recognize a category

Use labelled component images to learn signs of manufacturing defects.

Input: inspection image
Output: defect category

Analyze a signal

Use vibration recordings to learn patterns associated with equipment condition.

Input: vibration readings
Output: condition estimate

PyTorch provides the computation. We must supply suitable data, model choices and evaluation.

A model's answer is an estimate to validate, not automatically an engineering fact.
Ask students for a measurement from their own department. These are potential applications, not claims that a few lines of PyTorch solve them reliably. Labels are known target answers supplied with examples; explain that word before using it later.
02 / Why machine learning?A familiar distinction

Sometimes we know the rule.
Sometimes we need to learn a relationship.

A rule we already know

Convert Celsius to Fahrenheit.

F = C × 9 / 5 + 32

We write the formula. Training is unnecessary.

A relationship to estimate

Predict a building's electricity use from temperature, occupancy and past records.

There may be no simple formula that we already know. A model can fit patterns in historical data.

Use learning when it helps solve the problem. Not every calculation needs AI.
Ask: would you train a neural network just to convert units? Usually no. Learning still depends on human choices and assumptions. Domain equations may also be combined with learned models; do not present physics and ML as mutually exclusive.
02 / Training explainedNo code yet

What does it mean to train a model?

Training adjusts a model's internal numbers so its predictions better match known examples.

Data / input
The information given to the model, such as temperature and occupancy.
Target
The known answer in a training example, such as measured electricity use.
Prediction
The answer calculated by the model.
Model
A mathematical relationship that turns inputs into predictions.
Parameters / weights
Adjustable numbers inside that relationship.
Loss
A number describing how far predictions are from targets.
Training changes parameters. It does not mean manually rewriting the program for every example.
Give one verbal example: measured use is 12 units and the model estimates 10. There is a mismatch to measure. Do not introduce loss functions or differentiation formulas here. Inputs and targets must refer to the same example.
02 / Training explainedThe repeated calculation

Learning needs a repeatable calculation cycle.

1. Predict

Pass numerical inputs through the model.

→

2. Compare

Calculate loss against known targets.

→

3. Adjust

Update parameters, then repeat.

Why a framework helps

Real models can have millions of parameters and large amounts of data. Repeating all these calculations manually is impractical.

PyTorch's contribution

Fast tensor operations, automatic gradient calculation, model building blocks and update algorithms.

A gradient measures how loss changes with a parameter; an optimizer uses gradients to update parameters.
This is a map of the process, not today's coding task. Automatic differentiation computes derivatives of supported recorded operations; it does not choose the dataset or guarantee good learning. Evaluate on held-out data because lower training loss alone does not prove useful predictions.
02 / Two stagesLearning and inference

Learning a pattern is different from using it.

Training

Use examples with known answers, compare predictions, and update the model's parameters.

Past building records → adjust the model

Inference

Use a trained model to calculate a prediction for a new input, without updating its parameters.

Tomorrow's conditions → predicted energy use

PyTorch supports both stages. A model must be tested on data not used to fit it.

The examples in today's slides are calculations, not a trained AI model.
Our training explanation is the supervised-learning case. Other learning setups exist, but introducing them all would distract from the first-day purpose. Explain inference as using what was learned, without implying the model understands the building like a person.
03 / How PyTorch is madeOrigins and development

Built by engineers. Developed in the open.

Roots

Torch

The earlier Torch ecosystem provided scientific-computing and machine-learning tools, commonly used through Lua.

Public release / 2017

PyTorch

Originally developed at Facebook AI Research with contributors, bringing a Python-centered approach to tensor computing and deep learning.

Today

An open ecosystem

Maintained by a broad contributor community, with the PyTorch Foundation under the Linux Foundation.

PyTorch itself is software written and maintained by people. It is not a model trained on a dataset.

Official project: pytorch.org
Explain the difference between building the framework and training a model with it. PyTorch is not simply the old Lua interface renamed; it developed its own Python-centered system while sharing roots with Torch. Avoid attributing the entire project to one individual.
03 / How PyTorch is madeFrom our code to computation

Simple Python on top. Numerical engines underneath.

Our Python code

We describe data, operations and models using PyTorch's interface.

PyTorch core

Much of the numerical core is C++. It represents tensors and selects implementations for operations.

Compute routines

Optimized routines, often called kernels, perform the actual arithmetic.

Hardware

CPU or supported accelerators execute the work. CUDA supports NVIDIA GPU computation.

A short Python instruction can trigger a large optimized calculation underneath.

We use the Python interface today. We do not need to write C++ or GPU kernels.
This is a simplified architecture. The dispatcher selects implementations according to properties such as device and dtype; ATen is a core tensor library. PyTorch supports other accelerator backends too, so CUDA is not synonymous with every GPU. A kernel here means a compute routine, not the notebook runtime.
03 / How PyTorch is organizedRecognize the names, not the syntax

Four building blocks you will meet.

Tensors

Store numerical data and support calculations. This is where we begin today.

Autograd

Tracks supported operations when gradient tracking is enabled and computes derivatives needed for learning.

torch.nn

Provides neural-network building blocks and loss functions.

torch.optim

Provides optimizers that update model parameters using computed gradients.

Data representation first. Model and training details come after the foundations.
Do not explain constructors or backward calls yet. Students only need to know each component's responsibility. Ordinary tensors do not automatically track every calculation for training; gradient tracking must be enabled where appropriate.

04 / Understanding tensorsThe central object

A tensor is a numerical array
arranged along zero or more axes.

It can represent one value, a list of values, a table, or a higher-dimensional arrangement.

PyTorch knows the values, their arrangement and their numerical type.

It does not automatically know that these numbers are temperatures measured in degrees Celsius.

A tensor is a data container, not a model and not a prediction.
Use the computing meaning of tensor, not a full mathematical treatment of tensors under coordinate transformations. Ask what information is missing if someone just gives us [20, 25, 30]: units, time order, sensor identity, and so on.
04 / Understanding tensorsNames for arrangements

Three arrangements we already understand.

Scalar, vector and matrix are the 0D, 1D and 2D cases of tensors.
Physically point across the vector, then across and down the matrix. Dimension counts independent index directions, not the number of values. A vector of 100 readings is still one-dimensional. Higher-dimensional tensors can be introduced on Friday.
04 / Understanding tensorsRead a diagram before code

Shape tells us how many positions each axis has.

Shape (2, 3): two rows and three columns.

Dimensions = 2: the row axis and the column axis.

Number of values = 6: 2 × 3 measurements.

Six values do not mean six dimensions. Arrangement and quantity are different.

Rows and columns get their real-world meaning from us, not from PyTorch.
Ask students to describe the shape of three sensors measured four times, assuming the same arrangement: (3, 4), two dimensions, twelve values. Take verbal answers. Do not introduce tensor indexing syntax or ndim/numel calls on this slide.
04 / Understanding tensorsPurpose before an API

A list stores items. A tensor supports numerical work.

Python list

A general-purpose collection of objects, useful for organizing items.

Adding two lists joins their items together.

[1, 2] + [3, 4]
becomes [1, 2, 3, 4]

PyTorch tensor

A numerical array with a defined shape, data type and device.

Adding equal-shaped tensors adds matching entries.

[1, 2] plus [3, 4]
becomes [4, 6]

Tensors also connect to accelerated computation and PyTorch's automatic differentiation tools.

The same-looking values can have different behavior depending on their container.
The right-hand illustration is conceptual, not literal Python list syntax. Say this clearly. Tensors are not always faster for tiny operations; their value includes efficient large numerical workloads and integration with training. Do not imply every tensor requires a GPU.

05 / Worked example 1Represent, do not train

Store three temperature readings together.

Situation: one sensor records 20°C, 25°C and 30°C. We want a tensor containing those readings.

import torch

readings = torch.tensor([20.0, 25.0, 30.0])
print(readings)
tensor([20., 25., 30.])
import torch
Makes PyTorch available under its Python package name, torch.
readings =
Gives the resulting tensor a name we can reuse.
torch.tensor([...])
Creates a tensor from the supplied list of numbers.
print(readings)
Displays the tensor so we can inspect it.
What happened? We represented data. Nothing has learned a pattern yet.
Type this slowly. Explain square brackets as a Python list and parentheses as a function call. The dot in torch.tensor accesses something provided by torch. Decimal values request floating-point data under the usual defaults. PyTorch's display of 20. means 20.0, not a missing value. Reveal the output only after students explain the instructions.
05 / Worked example 2One operation, every entry

The sensor reads 2°C too low.

A calibration check found a constant error. Add 2°C to each reading to correct it.

corrected = readings + 2
print(corrected)

[20 + 2, 25 + 2, 30 + 2]

tensor([22., 27., 32.])
readings
The tensor created in the previous cell.
+ 2
Adds the same number to every entry.
corrected =
Stores the result under a new name. The original readings remain unchanged.
Why this is useful
We express the operation once rather than writing a separate addition for each measurement.
This is a known correction rule, not machine learning.
Ask for 20+2 first, then apply the same reasoning to the other values. General broadcasting rules come later; keep today's explanation to adding one scalar to a tensor. This assumes a known constant sensor error, not that all calibration problems are solved by adding two.
05 / Worked example 3Connect the code to familiar arithmetic

What was the average corrected temperature?

We have 22°C, 27°C and 32°C. The mean adds the values and divides by how many there are.

(22 + 27 + 32) / 3 = 27

average = corrected.mean()
print(average)
print(average.item())
tensor(27.)
27.0
corrected.mean()
Calculates the mean of all values in this tensor.
average
A scalar tensor holding one result: 27.
average.item()
Extracts its single value as an ordinary Python number.
Many readings → one summary. A calculation returning a number is not automatically an AI prediction.
Tie this to the earlier scalar slide. Both printed outputs represent the same numerical value but have different types. item works only when the tensor contains one element. Avoid dim arguments or per-column averages today.
06 / Preparing for FridayVocabulary, not another coding exercise

Every tensor has an arrangement, a type and a location.

Shape

How many positions are on each axis?

Our readings: (3,)
One axis with three values.

Data type / dtype

How are the numbers represented?

Our readings: floating-point values, normally float32.

Device

Where is the tensor stored and processed?

Normally the CPU unless another device is selected.

A GPU can process many numerical operations in parallel, but today's tiny examples do not need one.

Friday we will inspect these properties in code and learn why they matter.
The comma in (3,) is Python's way to write a one-element tuple; it does not mean a missing second dimension. float32 uses 32 bits per value and represents many decimal values approximately. Defaults can be changed, hence normally. Do not demonstrate device transfers or type conversion today.
06 / A clear mental modelWhat remains our responsibility

Installing PyTorch does not create intelligence.

PyTorch supplies

  • Numerical data containers and operations.
  • Tools for building and training models.
  • Support for efficient computation on compatible hardware.

We still decide

  • What problem and data the model should use.
  • How inputs, targets and units are represented.
  • How to check whether results are accurate and useful.

Our temperature examples demonstrate tensor calculations, not learned parameters or a trained model.

Good tools support good reasoning. They do not replace it.
Use this slide to prevent students from labelling every torch call as machine learning. Training requires a model and a learning procedure; tensor arithmetic is the foundation beneath that process.
